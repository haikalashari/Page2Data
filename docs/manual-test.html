Page2Data manual test page

Open this page in Chrome or Edge, then open Page2Data in the side panel. This page contains deliberately awkward tables. Expected results are listed in the blue box on each section.

Before you start

  • Run npm run build and load .output/chrome-mv3 unpacked.
  • Click the Page2Data toolbar icon while this page is active.
  • The initial scan should report 8 tables. The presentation and aria-hidden tables must be excluded.
  • All data rows stay as text. Cleaning changes column metadata, not the raw values.

5. Type inference

Expected after Clean → Apply types

  • Integer → Integer; Decimal, EN thousands, ID thousands, Currency → Number.
  • Date → Date; Boolean → Boolean; Empty → Empty; Mixed → Text.
  • Leading zero and Phone → Text (identifiers must not lose zeros).
  • 1.234.567 is treated as 1234567 and 1.234 as 1234 — a documented thousands-separator heuristic.

Other checks worth doing

  • Open chrome://extensions in the panel: it must show a friendly restricted-page error, not crash.
  • Reload the test page after installing the extension, then scan — this exercises the injection fallback for already-open tabs.
  • Close and reopen the side panel, then reload the browser: saved datasets must still be listed.
  • Inspect chrome://extensions → Page2Data → service worker / side panel DevTools to confirm no network requests happen while AI is disabled.
